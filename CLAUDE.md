# cage4D profile README

This repo is the GitHub profile README for **cage4D** (the special `cage4D/cage4D` repo).
Everything visible on the profile is generated by `scripts/build.mjs`. Do not hand-edit
the SVGs in `assets/`, `LAB.md`, or the block between the `artifacts` markers in
`README.md`; edit the build script and rerun it.

## Layout

| Path | What it is |
| --- | --- |
| `README.md` | Five panels plus a link to the lab page. Plain `<img>` tags only. |
| `LAB.md` | Generated page with the project cards ("things that escaped the lab"). Never hand-edit. |
| `assets/*.svg` | Generated panels. Each switches light/dark itself via `prefers-color-scheme`. `lab.svg` is the profile link to the lab page, `lab-header.svg` and `back.svg` sit on that page; `artifact-NN.svg` are the project cards (one per `PROJECTS` entry, regenerated and renumbered on every build). |
| `assets/stats.json` | Last fetched GitHub numbers. Created by the Action; not committed by hand. |
| `scripts/build.mjs` | Draws every panel, writes the lab link into the README and generates `LAB.md`. No dependencies. |
| `.github/workflows/readout.yml` | Runs the build daily, on manual dispatch, and when the build script changes. |

Run locally with `node scripts/build.mjs` (Node 18+). Without `GITHUB_TOKEN` it keeps the
last `stats.json` or draws a "no signal" state; with a token it fetches live stats.

## First-time setup (do this now)

1. **Fill in the TODO projects.** In `PROJECTS` near the top of `scripts/build.mjs`,
   `wave-play` and `transaction-queue` have `stack` and `purpose` set to `null`. Read each
   repo (`cage4D/wave-play`, `cage4D/transaction-queue`): README, `package.json` or other
   manifests, and the main source. Then fill in:
   - `stack`: lowercase, separated by ` · `, main tools only (5–6 max), e.g.
     `next.js · nestjs · prisma · postgresql`.
   - `purpose`: one or two lowercase sentences, about 25–40 words. Say what problem it
     solves; if it doesn't solve one, describe what it is. Quiet, slightly cryptic tone,
     no hype words. Match the two existing entries.
2. **Verify the two existing entries** against their repos and correct anything wrong:
   - `generative-music-studio`: confirm the frontend framework (assumed next.js) and the
     ORM (prisma vs drizzle).
   - `dev-overflow`: add the database/ORM if there is one.
3. **Check every repo name resolves** to a public repo under `cage4D`. If one is private
   or named differently, fix `name` (it is used for the link) or ask the user.
4. **Check the branch.** The profile link to the lab page assumes the default branch is
   `main` (`BRANCH` in `scripts/build.mjs`). Change it if the repo uses another name.
5. Run `node scripts/build.mjs`. It must not print `projects still marked TODO`.
6. Commit and push. Then, in the repo settings, make sure Actions are enabled and
   **Settings → Actions → General → Workflow permissions** is "Read and write", and run
   the "refresh readout" workflow once by hand so the stats panel fills with real data.

## Adding a project later

Append an object to `PROJECTS` (`name` = repo name, `status` = `"stable"`, `stack`,
`purpose`), keeping the tone above. Run the build (it rewrites `LAB.md` and the cards), commit. Pushing a change to the build
script also triggers the workflow, which regenerates the README.

## Content that is intentional, keep as is

- Header readouts: `origin: unlisted`, `signal: faint`, `intent: unclear`.
- Typing lines (`LINES`), in their current order.
- Only the handle `cage4D` appears; no real name.
- Monochrome only; no colour accents.
